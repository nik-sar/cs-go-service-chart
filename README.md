# cs-go-service-chart

Helm chart for deploying Go microservices to Kubernetes. Provides configurable Deployment, Service, Ingress, and CronJob resources.

## Features

- Configurable resource limits and requests
- Support for multiple replicas
- Environment variables via ConfigMaps, Secrets, and direct values
- HAProxy Ingress with URL rewrite support
- Optional CronJob workloads
- Automatic naming of resources with release name and namespace
- Image pull secrets support

## Installation

```bash
helm repo add cs-go-service-chart https://nik-sar.github.io/cs-go-service-chart/
helm repo update
helm install app-name cs-go-service-chart/cs-go-service-chart
```

## Configuration

### Main Parameters

| Parameter | Description | Default |
|-----------|-------------|---------|
| `replicaCount` | Number of pod replicas | `1` |
| `resources.limits.memory` | Memory limit for containers | `256Mi` |
| `resources.limits.cpu` | CPU limit for containers | `200m` |
| `resources.requests.memory` | Memory request for containers | `100Mi` |
| `resources.requests.cpu` | CPU request for containers | `100m` |
| `image.name` | Container image name (registry/repository) | `sample.host/sample-svc` |
| `image.tag` | Image tag | `stable` |
| `image.pullPolicy` | Image pull policy | `IfNotPresent` |
| `service.type` | Kubernetes Service type | `ClusterIP` |
| `service.port` | Service port exposed externally | `8080` |
| `service.targetPort` | Container port where the application listens | `8080` |
| `ingress.enabled` | Enable Ingress resource creation | `false` |
| `ingress.rules` | List of Ingress rules with rewrite targets | `[]` |
| `secrets` | List of environment variables sourced from Kubernetes Secrets | `[]` |
| `configMaps` | List of environment variables sourced from ConfigMaps | `[]` |
| `environments` | List of direct environment variables (key-value pairs) | `[]` |
| `crones` | List of CronJob configurations | `[]` |
| `imagePullSecrets` | List of image pull secrets for private registries | `[]` |

### Resource Naming Convention

All resources generated by this Helm chart follow a consistent naming pattern:
- **Deployment**: `{release-name}-deploy-{namespace}`
- **Service**: `{release-name}-svc-{namespace}`
- **Ingress**: `{release-name}-ingress-{namespace}-{index}` (one per rule)
- **CronJob**: `{cron-name}-cronjob`

Where:
- `{release-name}` - name specified during `helm install`
- `{namespace}` - namespace where the chart is deployed
- `{cron-name}` - name specified in each cron configuration
- `{index}` - sequential index of the ingress rule (0-based)

### Environment Variable Sources

This chart supports three types of environment variable sources:

#### 1. Direct Environment Variables (`environments`)
Simple key-value pairs injected directly into the container environment.

#### 2. Secrets (`secrets`)
Environment variables sourced from Kubernetes Secrets. Useful for sensitive data like passwords, API keys, and tokens.

#### 3. ConfigMaps (`configMaps`)
Environment variables sourced from Kubernetes ConfigMaps. Useful for configuration data that needs to be shared across pods.

### Ingress Configuration

The chart supports HAProxy Ingress controller with URL rewrite functionality. When `ingress.enabled` is set to `true`, an Ingress resource is created with the following annotations:
- `haproxy-ingress.github.io/rewrite-target`: URL path rewriting
- `ingressClassName: haproxy`: HAProxy ingress controller class

### CronJob Configuration

CronJobs can be configured for periodic tasks. Each cron job runs in its own container with specified arguments and schedule.

### Image Pull Secrets

For pulling images from private registries, you can specify image pull secrets that will be added to the pod specification.

### Complete Configuration Example

Below is a complete example of the `values.yaml` file using all possible parameters:

```yaml
# Main application parameters
replicaCount: 3

# Container resources
resources:
  limits:
    memory: "512Mi"
    cpu: "500m"
  requests:
    memory: "256Mi"
    cpu: "250m"

# Container image
image:
  name: "myregistry.com/my-org/my-app"
  tag: "v1.2.3"
  pullPolicy: IfNotPresent

# Secrets for accessing private images
imagePullSecrets:
  - name: "docker-registry-secret"
  - name: "ghcr-secret"

# Kubernetes Service
service:
  type: ClusterIP
  port: 8080
  targetPort: 8080

# Environment variables from different sources
environments:
  - envName: APP_ENV
    envValue: "production"
  - envName: DEBUG_MODE
    envValue: "false"
  - envName: LOG_LEVEL
    envValue: "info"

secrets:
  - envName: DB_PASSWORD
    secretName: "database-secrets"
    key: "password"
  - envName: API_KEY
    secretName: "api-secrets"
    key: "secret-key"

configMaps:
  - envName: CONFIG_FILE_PATH
    configName: "app-config"
    key: "configPath"
  - envName: API_BASE_URL
    configName: "app-config"
    key: "apiUrl"

# CronJobs for periodic tasks
crones:
  - name: "backup-cron"
    enabled: true
    schedule: "0 2 * * *"
    image:
      name: "curlimages/curl"
      tag: "1.0.3"
      args:
        - "-X"
        - "POST"
        - "http://backup-service/trigger"
  
  - name: "cleanup-cron"
    enabled: true
    schedule: "30 3 * * *"
    image:
      name: "alpine"
      tag: "latest"
      args:
        - "/scripts/cleanup.sh"
        - "--days=7"

# Ingress configuration (HAProxy)
ingress:
  enabled: true
  rules:
    - rewriteTarget: "/api/v1"
      hosts:
        - host: "api.myapp.com"
          paths:
            - path: "/api/v1"
              pathType: Prefix
            - path: "/api/docs"
              pathType: Prefix
    
    - rewriteTarget: "/admin"
      hosts:
        - host: "admin.myapp.com"
          paths:
            - path: "/admin"
              pathType: Prefix
        - host: "monitoring.myapp.com"
          paths:
            - path: "/grafana"
              pathType: Prefix
            - path: "/prometheus"
              pathType: Prefix
```

### Installation Example with Custom Values

```bash
# Create a file with custom values
cat > custom-values.yaml <<EOF
replicaCount: 2

image:
  name: "mycompany/app-backend"
  tag: "latest"

resources:
  limits:
    memory: "1Gi"
    cpu: "800m"

  - envName: ENVIRONMENT
    envValue: "staging"

  enabled: true
  rules:
    - rewriteTarget: "/api"
      hosts:
        - host: "staging-api.mycompany.com"
          paths:
            - path: "/api"
              pathType: Prefix
EOF

# Install the chart with custom values
helm install my-app cs-go-service-chart/cs-go-service-chart -f custom-values.yaml
```

### Detailed Structure Object Descriptions

#### Structure of `secrets` object

For obtaining environment variables from Kubernetes Secrets, the following structure is used:

```yaml
secrets:
  - envName:      STRING  # Environment variable name in container
    secretName:   STRING  # Kubernetes Secret name
    key:          STRING  # Key in Secret to get value from
```

**Example:**
```yaml
secrets:
  - envName: DB_PASSWORD
    secretName: database-secrets
    key: password
  - envName: API_KEY
    secretName: api-secrets
    key: secret-key
```

#### Structure of `configMaps` object

For obtaining environment variables from Kubernetes ConfigMaps, the following structure is used:

```yaml
configMaps:
  - envName:      STRING  # Environment variable name in container
    configName:   STRING  # Kubernetes ConfigMap name
    key:          STRING  # Key in ConfigMap to get value from
```

**Example:**
```yaml
configMaps:
  - envName: LOG_LEVEL
    configName: app-config
    key: logLevel
  - envName: API_BASE_URL
    configName: app-config
    key: apiUrl
```

#### Structure of `environments` object

For directly specifying environment variables, the following structure is used:

```yaml
environments:
  - envName:      STRING  # Environment variable name in container
    envValue:     STRING  # Variable value (string)
```

**Example:**
```yaml
environments:
  - envName: APP_ENV
    envValue: "production"
  - envName: DEBUG_MODE
    envValue: "false"
```

#### Structure of `crones` object

Each CronJob is configured using the following structure:

```yaml
crones:
  - name:         STRING   # CronJob name (used in resource name)
    enabled:      BOOLEAN  # Enable/disable this CronJob
    schedule:     STRING   # Schedule in cron format
    image:
      name:       STRING   # Image name (registry/repository)
      tag:        STRING   # Image tag
      args:       ARRAY    # Command arguments for the container
```

**Parameters:**
- `name`: CronJob name, used to generate resource name in format `{name}-cronjob`
- `enabled`: If `false`, CronJob will not be created
- `schedule`: Schedule in cron format (e.g., `"0 */2 * * *"` - every 2 hours)
- `image.name`: Full image name including registry
- `image.tag`: Image tag
- `image.args`: Array of arguments that will be passed to the container command

**Example:**
```yaml
crones:
  - name: backup-cron
    enabled: true
    schedule: "0 2 * * *"
    image:
      name: "curlimages/curl"
      tag: "1.0.3"
      args:
        - "-X"
        - "POST"
        - "http://backup-service/trigger"
```

#### Structure of `imagePullSecrets` object

For accessing images from private registries, the following structure is used:

```yaml
imagePullSecrets:
  - name: STRING  # Kubernetes Secret name with registry credentials
```

**Example:**
```yaml
imagePullSecrets:
  - name: docker-registry-secret
  - name: ghcr-secret
```

#### Structure of `ingress.rules` object

For Ingress configuration, a complex nested structure is used:

```yaml
ingress:
  enabled: true  # Enable Ingress resource creation
  rules:
    - rewriteTarget: STRING  # Target path for rewrite (e.g., "/api/rest")
      hosts:
        - host: STRING       # Host domain name
          paths:
            - path: STRING       # URL path
              pathType: STRING   # Path type (Prefix or Exact)
```

**Parameters:**
- `rewriteTarget`: Target path where requests will be redirected
- `hosts[].host`: Domain name that the Ingress will serve
- `hosts[].paths[].path`: URL path where the service is accessible
- `hosts[].paths[].pathType`: Path type - `Prefix` (prefix) or `Exact` (exact match)

**Example:**
```yaml
ingress:
  enabled: true
  rules:
    - rewriteTarget: "/api/rest"
      hosts:
        - host: "api.example.com"
          paths:
            - path: "/api/rest"
              pathType: Prefix
            - path: "/api/docs"
              pathType: Prefix
        - host: "admin.example.com"
          paths:
            - path: "/admin"
              pathType: Prefix
```

#### Default CronJob Parameters

Each created CronJob has the following fixed settings:
- `successfulJobsHistoryLimit: 0` - successful Jobs are deleted immediately after execution
- `failedJobsHistoryLimit: 1` - only 1 failed Job is kept for debugging
- `restartPolicy: OnFailure` - container restart only on failure
- `imagePullPolicy: IfNotPresent` - image pull policy "if not present"
